# AirClimat.pmr Bot — многофункциональный, бесплатный кроме одной функции

Телеграм-бот для AirClimat.pmr. Изначально — калькулятор падения КПД
обогрева кондиционера по погоде, сейчас — набор инструментов для лидов,
гарантии, склада, актов и B2B-обслуживания. **Почти всё работает без
единого платного API** — погода/геокодинг через Open-Meteo (бесплатно, без
ключа), классификация кондиционеров, расчёт мощности, расчёт акта и склад —
чистый Python без ИИ. Единственное исключение — **распознавание фото актов
через Claude** (см. отдельный раздел ниже), это осознанное решение,
принятое явно, и оно опционально: без `ANTHROPIC_API_KEY` эта одна функция
просто выключена, всё остальное работает как обычно.

## Кнопочное меню вместо команд

С `/start` (и в любой момент через `/menu`) бот показывает **постоянную
клавиатуру снизу экрана**, кнопки зависят от роли:

- Монтажнику: 🧾 Посчитать акт, 📦 Материал (приход/расход), 📷 Акт с фото (адрес)
- Админу — дополнительно: 📊 Склад, 📋 Акты в очереди, 🏢 B2B точки
- Обычному клиенту (не админ и не монтажник): 🧮 Подбор мощности,
  🛡 Проверить гарантию

Команды (`/actcalc`, `/stock_in`, `/material`, `/act`, `/stock`,
`/acts_pending`, `/b2b_list`, `/calc`, `/warranty`) при этом никуда не делись
и продолжают работать текстом — кнопки просто отправляют то же самое
действие, чтобы не нужно было ничего печатать. `📦 Материал (приход/расход)`
и `📷 Акт с фото` через кнопку задают уточняющие вопросы по шагам (материал
→ приход/расход → количество; адрес → фото/«пропустить»), а не требуют
формат с `|` как текстовые команды.

**Устаревшая клавиатура на телефоне клиента:** Telegram хранит кнопки
снизу экрана на стороне клиента — если названия кнопок поменялись в новой
версии бота, у людей, кто не открывал бота с тех пор, останутся старые
подписи. Нажатие такой устаревшей кнопки просто не совпадёт ни с одним
текущим `BTN_*` — бот для админов/монтажников ответит «Не понял команду.
Нажмите /menu...» (а не попытается угадать, что это, через флоу
КПД-калькулятора — тот предназначен только для обычных клиентов и не
должен цеплять админов/монтажников, даже если текст не распознан).
`/menu` пересобирает клавиатуру заново с актуальными подписями.

## Автомиграция схемы БД


При расширении `/calc` тремя новыми вопросами (потолки/окна/техника) в
таблицу `leads` понадобились новые колонки. Бот сам добавляет их при
старте (`_ensure_column` в `db.py`, через `ALTER TABLE ... ADD COLUMN`),
если их ещё нет — никаких ручных действий с базой не требуется, старые
записи о лидах просто останутся с пустыми значениями в новых полях.

## Единый список материалов (без задвоения)

`/material`, автосписание внутри `/actcalc` и текстовые команды склада все
используют **один и тот же список материалов** — `act_catalog.STOCK_MATERIALS`
(19 позиций: 4 с фиксированной ценой + 15 без цены, ровно те, что
фигурируют в актах). Раньше у кнопки `/material` был свой отдельный
укороченный список из 7 материалов с немного другими названиями («Труба
Ø6», «Кронштейны», «Болты», «Металлопласт»), из-за чего один и тот же
физический материал мог завестись на складе под двумя разными именами —
если списать его через `/material`, а потом через `/actcalc`.

`/material` теперь единый для прихода и расхода: сначала выбирается
материал, потом кнопками — «⬆️ Приход» или «⬇️ Расход», потом количество.
Доступен и монтажникам, и админам одинаково — раньше приход был только у
админа, теперь оба типа операций доступны всем, у кого вообще есть доступ
к складу.

**Если вы уже пользовались ботом до этого исправления** — при следующем
старте бот **автоматически перенесёт** остатки со старых названий на новые
(«Труба Ø6» → «Труба медная 6.35мм», «Кронштейны» → «Кронштейн», «Болты» →
«Болт/гайка/шайба», «Металлопласт» → «Труба металлопластиковая ф16», и
аналогично для Ø9/Ø12/Ø15). Если на новом имени уже что-то было — количества
сложатся, старая строка удалится. Разовая операция, безопасно выполняется
при каждом запуске (после первого раза просто ничего не делает). В логах
при этом будет видно `Перенёс остаток материала: «...» -> «...»`.

## Функции

### Для клиентов (публичные команды)

- **Свободный текст с моделью кондиционера** — падение КПД обогрева по
  текущей погоде (как раньше — см. `classifier.py`).
- **`/calc`** — подбор рекомендуемой мощности: бот задаёт клиенту вопросы по
  очереди — площадь помещения (м²), высота потолков (до/выше 2.7 м), куда
  выходят окна (север/юг/восток/запад/нет окон — юг и запад считаются
  «солнечной» стороной), есть ли тепловыделяющая техника в помещении
  (компьютеры, холодильники, серверы, кухонное/торговое оборудование),
  последний ли этаж, физлицо или компания, контакт. Каждый фактор —
  независимая поправка +5% к расчётной мощности. Результат уходит клиенту
  сразу, а карточка заявки со всеми ответами — вам в личку (см.
  ADMIN_CHAT_IDS ниже). **Точную цену бот не называет** — в прайсе
  поставщика это дилерские/оптовые цены, а не ваша розница, показывать их
  клиенту нельзя.
- **`/warranty`** — проверка гарантии по установке, зарегистрированной на
  этот chat_id (регистрирует админ через `/new_install`, см. ниже).
- **`/city <город>`** — сменить город для погоды.
- **`/whoami`** — узнать свой chat_id (нужно для настройки админов).
- **`/help`** — список команд (сокращённый для клиентов, расширенный для
  админов).

### Для монтажников (INSTALLER_CHAT_IDS)

Отдельная, более узкая роль — только склад и акты, без доступа к лидам,
B2B-контрактам и регистрации установок:

- **`/actcalc`** — **посчитать акт по позициям**, как в бумажном шаблоне
  `АВР_Монтаж_Кондиционеров`:
  1. Выбираете группу мощности кнопкой: **7-9-12 / 18 / 24** (это группировка
     цен монтажа из акта, не путать с классами 09K/12K/18K/24K из КПД-калькулятора).
  2. Дальше три страницы позиций — **Работы**, **Материалы (цена
     фиксирована)**, **Материалы (укажите цену сами)**. Жмёте на нужную
     позицию → бот спрашивает количество (для позиций с фиксированной ценой
     этого достаточно — цену бот уже знает) → для позиций без цены в
     шаблоне (трубы конкретного диаметра, изолента, дюбели, выезд и т.п.)
     ещё спросит цену за единицу.
  3. «✅ Завершить акт» — бот считает итог, **автоматически списывает
     материалы со склада** (по тем же названиям, что в `/stock`/`/material`;
     если позиции ещё нет на складе — заводит её сам) и сохраняет акт в базу.
  Работы на склад не влияют — списываются только материалы.
- **`/material`** — быстрое кнопочное списание одного материала вне акта
  (для мелких случаев типа «докупили и сразу использовали 2 кронштейна»).
- **`/act Адрес`** — то же самое, что у админа (см. ниже): адрес + фото/
  «пропустить». Это отдельный, более простой механизм для случаев, когда
  бумажный акт с подписью клиента фотографируется как есть (без разбивки по
  позициям) — на будущее туда добавится распознавание фото через ИИ, чтобы
  автоматически вытаскивать ФИО/телефон/модель/адрес в базу клиентов.

Админы (ADMIN_CHAT_IDS) автоматически имеют и все права монтажника — им не
нужно отдельно прописываться в INSTALLER_CHAT_IDS.

### Для вас/Евгения (админ-команды, только для ADMIN_CHAT_IDS)

- **`/new_install`** — зарегистрировать установку для гарантии/напоминаний:
  ```
  /new_install Иванов +373... | TCL 12K простой инвертор | 12K | Тирасполь | 2026-09-01 | 24 | 555666777
  ```
  Поля через `|`: клиент/телефон, модель (обязательны только эти два),
  класс мощности, город, дата установки (по умолчанию сегодня), гарантия в
  месяцах (по умолчанию 24), chat_id клиента в Telegram. **chat_id клиента
  нужен, чтобы бот мог САМ написать клиенту** напоминание о ТО и запрос
  отзыва — без него установка просто лежит для внутреннего учёта. Узнать
  chat_id клиента можно, попросив его прислать боту `/whoami`.

- **`/stock`** — остатки склада.
- **`/stock_init Название | Ед.изм | Количество`** — завести материал (или
  переустановить остаток).
- **`/stock_use Название | Количество`** — списать расход текстовой командой
  (для админа; монтажникам удобнее кнопочный `/material` или полноценный
  разбор акта через `/actcalc`, см. выше).
- **`/stock_in Название | Количество`** — оприходовать материал (поступление
  на склад). Если материала ещё нет — заводит его сам с единицей «ед.» —
  поправьте потом через `/stock_init` при необходимости.

- **`/act Адрес`** — начать акт выполненных работ: бот попросит фото
  объекта (или напишите «пропустить»). Сохраняется в очередь. **Доступно
  и монтажникам** (INSTALLER_CHAT_IDS), не только админам.
- **`/acts_pending`** — список актов, ожидающих оформления (только админ).

- **`/b2b_add Договор | Точка | [Периодичность,дн]`** — добавить точку
  обслуживания по B2B-контракту (по умолчанию каждые 90 дней).
- **`/b2b_done Договор | Точка`** — отметить точку обслуженной сегодня.
- **`/b2b_list`** — статус всех точек (просрочено/в порядке).

### Автоматика (фоновая ежедневная задача)

Раз в день (`B2B_CHECK_HOUR_UTC`, по умолчанию 7:00 UTC) бот сам:

- пишет клиенту запрос отзыва через `REVIEW_REQUEST_DAYS_AFTER_INSTALL`
  дней после установки (по умолчанию 3) — ответ клиента сохраняется в
  таблицу `reviews`;
- пишет клиенту напоминание о сезонном ТО каждые
  `MAINTENANCE_REMINDER_INTERVAL_DAYS` дней (по умолчанию 180 ≈ раз в
  полгода) с момента установки/последнего напоминания;
- присылает вам (ADMIN_CHAT_IDS) сводку по просроченным B2B-точкам.

Это всё работает только для установок с указанным chat_id клиента.

## Настройка

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="токен от @BotFather"
export ADMIN_CHAT_IDS="123456789"            # ваш chat_id (и Евгения, если нужно, через запятую)
export INSTALLER_CHAT_IDS="555666777"        # chat_id монтажников (склад + акты, без остального)
python bot.py
```

Как узнать chat_id: попросите человека запустить бота и написать ему
`/whoami`, скопируйте число. Владельцам бота (полный доступ) — в
`ADMIN_CHAT_IDS`, монтажникам (только склад + акты) — в `INSTALLER_CHAT_IDS`.

Необязательные переменные:
- `ANTHROPIC_API_KEY` — включает распознавание фото актов через Claude (см.
  раздел ниже). Без неё эта одна функция выключена, всё остальное работает.
- `ACT_OCR_MODEL` — модель для распознавания (по умолчанию `claude-sonnet-5`).
- `AC_BOT_LOG_PATH` — путь к JSONL-логу диалогов КПД-калькулятора (по
  умолчанию `dialogs.jsonl`).
- `DB_PATH` — путь к файлу базы данных SQLite (по умолчанию `bot_data.db`).
- `REVIEW_REQUEST_DAYS_AFTER_INSTALL`, `MAINTENANCE_REMINDER_INTERVAL_DAYS`,
  `B2B_CHECK_HOUR_UTC` — тонкая настройка автоматики (см. выше).

## ⚠️ Персистентное хранилище на Railway

Файловая система на Railway **эфемерная** — при каждом новом деплое (после
`git push`) файл базы `bot_data.db` (и лог `dialogs.jsonl`) обнуляются.
Это означает потерю склада, лидов, установок, B2B-точек при каждом
обновлении кода!

Чтобы данные сохранялись между деплоями, подключите **Railway Volume**:

1. В сервисе на Railway откройте вкладку **Settings → Volumes**.
2. Нажмите **New Volume**, укажите mount path, например `/data`.
3. В Variables добавьте `DB_PATH=/data/bot_data.db` (и, если нужно,
   `AC_BOT_LOG_PATH=/data/dialogs.jsonl`).
4. Передеплойте — теперь база будет жить на постоянном диске, а не в
   контейнере, и переживёт любой следующий деплой.

Без volume бот прекрасно работает для тестирования, но реальные
данные клиентов копить в таком режиме нельзя.

## Как это устроено без ИИ

Как и раньше (см. предыдущую версию README) — классификация типа
кондиционера и расчёт КПД обогрева в `classifier.py` полностью
детерминированы: ключевые слова + оцифрованные таблицы + линейная
интерполяция, кнопки там, где нужно уточнение. Новые функции (`/calc`,
склад, акты, B2B) — обычная бизнес-логика без каких-либо ИИ-вызовов,
только SQLite (`db.py`) и Telegram API.

## Точность калькулятора мощности (`/calc`)

Формула — общепринятая отправная точка (100 Вт/м² при стандартном потолке),
с поправками +5% на последний этаж, +5% на солнечную сторону, +5% на
высокие потолки и +5% на тепловыделяющую технику. Это
ориентировочный расчёт для быстрой подсказки клиенту и квалификации лида,
**не инженерный точный подбор** — финальное решение всегда через менеджера
(бот сам это и говорит клиенту).

## Распознавание фото актов через Claude (единственная платная функция)

Когда монтажник фотографирует подписанный бумажный акт после `/act` (или
кнопки 📷 «Акт с фото»), бот отправляет фото в **Claude (Anthropic API)** и
автоматически извлекает:

- ФИО клиента
- Телефон
- Модель кондиционера
- Дату акта
- Адрес монтажа

...и сразу создаёт запись в базе клиентов/установок (`db.installations`,
`source="ocr"`) — без ручного набора текста. Монтажнику приходит сводка
того, что распознано; если что-то не так — можно поправить вручную через
`/new_install`. Если уверенность распознавания низкая или часть полей не
удалось прочитать — админу дополнительно прилетает предупреждение с
просьбой перепроверить.

**Это единственное место во всём боте, где используется платный ИИ** — всё
остальное (классификация кондиционеров, калькулятор мощности, расчёт акта,
склад) по-прежнему работает бесплатно, без единого вызова ИИ.

### Настройка

```bash
export ANTHROPIC_API_KEY="sk-ant-..."      # обязательно для этой функции
export ACT_OCR_MODEL="claude-sonnet-5"      # необязательно, значение по умолчанию
```

Если `ANTHROPIC_API_KEY` не задан — распознавание просто тихо пропускается
(акт по-прежнему сохраняется с фото и адресом, как раньше), никаких ошибок
не будет — бот полностью работоспособен и без этого ключа.

### `/clients` (админ)

Показывает последние 15 записей в базе клиентов/установок — включая те,
что попали туда через распознавание фото (помечены `[ocr]` и уровнем
уверенности), чтобы можно было быстро пробежаться глазами и проверить
качество распознавания.

### Точность и ограничения

- Распознавание рукописного текста никогда не будет 100% точным —
  особенно неразборчивый почерк, зачёркивания, плохое освещение на фото.
  Каждая запись хранит `ocr_confidence` (high/medium/low) и список
  `unclear_fields`, которые вернул Claude — используйте `/clients` для
  выборочной проверки, особенно записей с низкой уверенностью.
- Дата акта: если год на документе не указан явно, Claude сам
  предполагает ближайший подходящий год относительно текущей даты — при
  сомнении лучше проверить вручную.
- Фото исходного акта (`file_id`) сохраняется в `ocr_raw_photo_file_id` —
  можно будет позже добавить команду для повторного скачивания оригинала
  из Telegram, если понадобится сверить с бумажным документом.

## Запись клиентов в Google Sheets («Список клиентов»)

После успешного распознавания фото акта (см. выше) бот дополнительно
дописывает строку в вашу таблицу **«Список клиентов»** (лист «Клиенты») —
туда же, где вы уже ведёте базу вручную. Так распознанные ФИО, телефон,
адрес, модель кондиционера и исполнитель сразу попадают в единое место, а
не только во внутреннюю SQLite-базу бота.

Колонки заполняются так:

| Колонка | Откуда берётся |
|---|---|
| Дата добавления | сегодняшняя дата |
| ФИО | распознано с фото |
| Телефон | распознано с фото |
| Email | оставляется пустым |
| Адрес | распознано с фото |
| Оборудование | распознанная модель кондиционера |
| Дата установки | дата акта, формат ММ.ГГГГ (как в вашей инструкции к таблице) |
| Последнее ТО | оставляется пустым |
| Тип услуги | всегда «Установка» (акты `/act` — это акты монтажа) |
| Сумма | оставляется пустым (акт с фото не содержит расчёта суммы) |
| Исполнитель | имя монтажника, если указано в `INSTALLER_NAMES`, иначе его chat_id |
| Следующее ТО | дата установки + 6 месяцев |
| Статус | всегда «Активный» |
| Дата последнего контакта | сегодняшняя дата |
| Примечания | уверенность распознавания + список неясных полей, если есть |

### Настройка

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте
   проект (или используйте существующий), включите **Google Sheets API**.
2. Создайте **сервисный аккаунт** (Service Account) → создайте для него
   JSON-ключ → скачайте файл.
3. Откройте таблицу «Список клиентов» в Google Sheets → кнопка
   «Настройки доступа» → добавьте email сервисного аккаунта (поле
   `client_email` внутри скачанного JSON) с правом **Редактор**.
4. На Railway добавьте переменные:
   ```bash
   GOOGLE_SERVICE_ACCOUNT_JSON='{"type": "service_account", "client_email": "...", ...}'   # весь JSON-файл одной строкой
   CLIENTS_SPREADSHEET_ID="1AI-e-W5KlHt9FTxyc0049D_5TsUmXZP0hmaqTYpGJPw"   # ID вашей таблицы «Список клиентов» — уже подставлен по умолчанию в коде
   INSTALLER_NAMES="111111111:Дмитрий,222222222:Евгений"   # необязательно, chat_id -> имя для колонки «Исполнитель»
   ```

Без `GOOGLE_SERVICE_ACCOUNT_JSON` эта запись просто пропускается — акт и
локальная база клиентов всё равно заполняются как обычно, ошибок не будет.
Если запись в Sheets не удалась (например, доступ не тот, таблица
переименована) — монтажнику и админу приходит предупреждение, но сам акт и
локальная запись всё равно сохраняются.

**Пока не синхронизируется:** установки, зарегистрированные вручную через
`/new_install` (у этой команды пока нет полей телефон/адрес) — работает
только автоматический путь через распознавание фото.

## Склад материалов в Google Sheets («Склад материалов»)

Отдельная таблица — [«Склад материалов»](https://docs.google.com/spreadsheets/d/1YnXhKkNAnsliRpIrdoz4SWPEGOgzx3umgbNd51TnLJ0/edit),
с **двумя листами**: **SQLite остаётся источником истины** — таблица
склада (`db.inventory`) как и раньше живёт там же, где всё остальное
(лиды, установки, акты); оба листа в Sheets — это витрина для просмотра.

- **«Остатки»** — текущий снимок склада (Материал | Ед. изм. | Остаток |
  Обновлено, отсортировано по названию), полностью перезаписывается при
  каждом изменении.
- **«Журнал»** — полная история прихода и расхода **по датам**, по одной
  строке на каждую операцию: Дата | Время | Материал | Ед. изм. | Операция
  (Приход/Расход) | Количество | Остаток после | Исполнитель | Источник
  (какая команда/акт вызвали движение). Только дописывается, ничего не
  перезаписывается — полноценный журнал для учёта, а не просто текущий
  остаток.

Оба листа обновляются автоматически после:

- `/stock_init`, `/stock_use`, `/stock_in` (текстовые команды админа);
- кнопочного списания `/material` и кнопочного прихода (и списание, и
  приход — оба режима);
- `/actcalc`, если в акте были материалы (работы на склад не влияют; если
  материалов несколько — в «Журнал» попадает отдельная строка на каждый).

Оба листа создаются автоматически при первой записи, если их ещё нет в
таблице (в том числе если вы создавали таблицу вручную с другим листом по
умолчанию) — руками ничего заводить не нужно.

Плюс есть ручная команда **`/sync_stock_sheet`** (админ) — принудительно
обновить лист «Остатки» в любой момент, не дожидаясь следующего изменения
склада (полезно сразу после первой настройки интеграции). Журнал эта
команда не трогает — туда попадают только реальные движения.

И **`/stock_reset`** (админ) — обнуляет остатки **всех** материалов на
складе разом (список материалов и единицы измерения не трогает, только
количество). Пригодится, чтобы стереть тестовые/пробные данные и начать
реальный учёт с нуля. Синхронизирует лист «Остатки» сразу после сброса;
записи в «Журнал» не делает (это не реальное движение, а обнуление).

### Настройка

Использует тот же сервисный аккаунт, что и «Список клиентов» (см. выше) —
если он уже настроен, достаточно **дополнительно** дать этому сервисному
аккаунту доступ «Редактор» к таблице «Склад материалов» (то же «Настройки
доступа» → email сервисного аккаунта). Отдельная переменная не обязательна:

```bash
STOCK_SPREADSHEET_ID="1YnXhKkNAnsliRpIrdoz4SWPEGOgzx3umgbNd51TnLJ0"   # уже подставлен по умолчанию в коде
```

Без `GOOGLE_SERVICE_ACCOUNT_JSON` синхронизация склада, как и синхронизация
клиентов, просто пропускается — все складские команды работают как обычно,
только без зеркала в Sheets.

## Экспорт актов в файлы (.docx / .xlsx)

Два независимых формата экспорта, оба — только для структурированных актов
из `/actcalc` (там есть цены и позиции; у простых фото-актов из `/act`
таких данных нет — они просто хранят фото и адрес).

- **`/act_export <номер> | [Заказчик] | [Адрес] | [Модель]`** (админ) —
  генерирует **один акт в .docx** по точному образцу вашего шаблона
  `АВР_Монтаж_Кондиционеров`: шапка (номер, дата, модель, заказчик, адрес,
  исполнитель), таблица «Работы» + «Материалы» с ценами и итогом,
  стандартный текст про выполнение работ, строки для подписи. Заказчик,
  адрес и модель — необязательные аргументы (в `/actcalc` они не
  запрашиваются, только позиции и цены): если не указать — в файле
  останутся пустые линии для дозаполнения от руки, как на бумажном бланке.
  Номера актов — через `/material_acts`.
- **`/material_acts`** (админ) — список последних актов, посчитанных через
  `/actcalc`, с номерами (чтобы знать, что подставлять в `/act_export`).
- **`/acts_export`** (админ) — **сводный Excel по ВСЕМ актам сразу**
  (и простым фото-актам, и структурированным), одна строка на акт: ID,
  дата, тип, адрес/группа, сумма (для `/actcalc`), исполнитель, статус —
  для бухгалтерии/отчётности, а не для печати каждого акта отдельно.

Оба формата собираются на лету при запросе (не хранятся заранее) и
присылаются прямо в Telegram как файл.
