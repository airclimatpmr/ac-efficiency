# AC Efficiency Bot — AirClimat.pmr (бесплатная версия, без ИИ)

Телеграм-бот: клиент пишет модель кондиционера → бот узнаёт текущую уличную
температуру → определяет тип кондиционера и мощность (по ключевым словам в
тексте или кнопками, если не угадал) → считает падение КПД обогрева по
оцифрованным графикам с klimresh.by.

**Никакого платного API не используется.** Ни Anthropic, ни OpenAI, ни
какой-либо другой ИИ-сервис — вся логика в `classifier.py`: ключевые слова +
таблицы + линейная интерполяция. Погода и геокодинг городов — через
Open-Meteo, тоже бесплатно и без ключа.

## Как это устроено без ИИ

Раньше классификацию и расчёт делал Claude по системному промпту. Теперь то
же самое — но детерминированными правилами:

1. **Определение типа** (`classifier.keyword_guess_type`) — ищет в тексте
   клиента ключевые слова: "Nordic"/"Arctic"/"Lyra"/"Winter" → зимний
   инвертор, "Prestige"/"Ultra"/"Hyper" → суперинвертор, явное упоминание
   "on/off" → неинверторный, "зимний комплект"/"подогрев поддона" →
   инвертор с заводским комплектом, просто "инвертор" → простой инвертор.
   Если ничего не подошло — бот **показывает кнопки** с 5 типами на выбор,
   а не гадает.

2. **Определение мощности** (`classifier.guess_capacity_class`) — нужно
   только для "зимнего инвертора" (там 4 разные кривые: 09K/12K/18K/24K).
   Ищет в тексте явные указания BTU/кВт/тыс. Если не нашёл — **показывает
   кнопки** с классами мощности. Для типа "инвертор с заводским зимним
   комплектом" мощность желательна, но необязательна — по умолчанию
   используется 12K с пометкой в ответе.

3. **Расчёт %** — линейная интерполяция между оцифрованными точками
   графиков (`CURVE_TYPE2`, `CURVES_TYPE4`, `CURVE_TYPE5` в `classifier.py`).

Важно про регулярки для мощности: они специально требуют явного признака
единицы измерения (BTU/K/тыс/кВт) рядом с числом — просто число 9000/12000
внутри артикула модели (например "XYZ-9000") НЕ считается указанием
мощности, чтобы не давать ложных срабатываний.

## Точность цифр

Опорные точки в `classifier.py` оцифрованы вручную по скриншотам трёх
графиков с сайта klimresh.by (простой инвертор, зимний инвертор — 4 кривые
по классам мощности, суперинвертор). Считывание "на глаз" по клеточкам
графика — точность ±5-10 процентных пунктов. Для дружелюбного бота этого
достаточно, для инженерных расчётов — нет.

## Настройка

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="токен от @BotFather"
export AC_BOT_LOG_PATH="dialogs.jsonl"   # необязательно, по умолчанию dialogs.jsonl
python bot.py
```

Всё. Ключ Anthropic/OpenAI не нужен — платить не за что, кроме, собственно,
хостинга самого бота (или бесплатного VPS/бесплатного тарифа Railway/Render).

## Выбор города

По умолчанию город **не задан** — при первом сообщении в чате (когда клиент
пишет модель кондиционера) бот сначала спросит "Из какого вы города?", и
только после ответа продолжит расчёт (город нужен, чтобы узнать погоду).
Дальше город запоминается на весь чат и повторно не спрашивается. Найденные
координаты — через бесплатный Geocoding API Open-Meteo (без ключа).

Поменять уже сохранённый город можно в любой момент командой `/city
<название>`, например `/city Тирасполь`.

Привязка города к чату хранится в памяти процесса (`CHAT_CITIES`) — при
перезапуске бота сбрасывается, и бот снова спросит город при следующем
сообщении. Если нужна постоянная привязка — вынесите этот словарь в файл
или БД.

## Логирование диалогов

Каждое взаимодействие дописывается отдельной строкой в JSONL-файл
(`AC_BOT_LOG_PATH`, по умолчанию `dialogs.jsonl`) — один JSON-объект на
строку: время, chat_id, город, уличная температура, что написал клиент и
итоговая классификация (тип, класс мощности, была ли мощность угадана
автоматически). Формат удобно:

- смотреть в реальном времени: `tail -f dialogs.jsonl`
- построчно парсить скриптом на Python (`json.loads` на каждую строку)
- загрузить в pandas: `pandas.read_json("dialogs.jsonl", lines=True)`

Именно по этому логу удобно вручную сверять, насколько разумно бот
классифицирует реальные модели клиентов, и по итогам расширять словари
ключевых слов в `classifier.py` (например, добавить туда конкретные линейки
TCL/Mystery/AERVITA, которые вы продаёте, если увидите, что бот часто не
может их опознать и показывает кнопки).

## Что можно доработать дальше

- `PENDING_CITY` / `PENDING_TYPE` / `PENDING_CAPACITY` / `CHAT_CITIES`
  сейчас в памяти процесса — для продакшена лучше вынести в Redis/SQLite,
  иначе при перезапуске бота теряются незавершённые диалоги и привязки
  городов.
- Расширить словари ключевых слов в `classifier.py` под конкретные модели,
  которые реально пишут ваши клиенты (см. лог диалогов).
- Добавить ежедневную подписку: раз в день сам присылать апдейт по ранее
  указанной модели (нужна база подписчиков + модель + город).
- Добавить триггер на резкую жару/мороз в прогнозе (Open-Meteo отдаёт и
  прогноз, не только текущую температуру — можно дёргать `daily` вместо
  `current`).
- Ротация/архивация лог-файла диалогов, если поток сообщений станет большим.
- Если позже всё-таки захочется вернуть ИИ-классификацию (например, для
  моделей, которые совсем не покрываются словарём) — можно точечно
  подключить бесплатный лимит другого провайдера (например, Google Gemini
  через AI Studio) только для случая "кнопки не помогли", не трогая
  остальную бесплатную логику.
