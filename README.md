# AirClimat.pmr Bot — многофункциональный, полностью бесплатный (без ИИ)

Телеграм-бот для AirClimat.pmr. Изначально — калькулятор падения КПД
обогрева кондиционера по погоде, сейчас — набор инструментов для лидов,
гарантии, склада, актов и B2B-обслуживания. **Никакого платного API** — ни
Anthropic, ни OpenAI. Погода/геокодинг — Open-Meteo (бесплатно, без ключа).

## Кнопочное меню вместо команд

С `/start` (и в любой момент через `/menu`) бот показывает **постоянную
клавиатуру снизу экрана**, кнопки зависят от роли:

- Монтажнику: 🧾 Посчитать акт, 📦 Списать материал, 📷 Акт с фото (адрес)
- Админу — дополнительно: ➕ Приход материала, 📊 Склад, 📋 Акты в очереди,
  🏢 B2B точки
- Обычному клиенту (не админ и не монтажник): 🧮 Подбор мощности,
  🛡 Проверить гарантию

Команды (`/actcalc`, `/stock_in`, `/material`, `/act`, `/stock`,
`/acts_pending`, `/b2b_list`, `/calc`, `/warranty`) при этом никуда не делись
и продолжают работать текстом — кнопки просто отправляют то же самое
действие, чтобы не нужно было ничего печатать. `➕ Приход материала` и
`📷 Акт с фото` через кнопку задают уточняющие вопросы по шагам (название →
количество; адрес → фото/«пропустить»), а не требуют формат с `|` как
текстовые команды.

## Автомиграция схемы БД

При расширении `/calc` тремя новыми вопросами (потолки/окна/техника) в
таблицу `leads` понадобились новые колонки. Бот сам добавляет их при
старте (`_ensure_column` в `db.py`, через `ALTER TABLE ... ADD COLUMN`),
если их ещё нет — никаких ручных действий с базой не требуется, старые
записи о лидах просто останутся с пустыми значениями в новых полях.

## Единый список материалов (без задвоения)

`/material` (списание), `➕ Приход материала` и автосписание внутри
`/actcalc` теперь используют **один и тот же список материалов** —
`act_catalog.STOCK_MATERIALS` (19 позиций: 4 с фиксированной ценой + 15 без
цены, ровно те, что фигурируют в актах). Раньше у кнопки `/material` был
свой отдельный укороченный список из 7 материалов с немного другими
названиями («Труба Ø6», «Кронштейны», «Болты», «Металлопласт»), из-за чего
один и тот же физический материал мог завестись на складе под двумя
разными именами — если списать его через `/material`, а потом через
`/actcalc`.

**Если вы уже пользовались ботом до этого исправления** — при следующем
старте бот **автоматически перенесёт** остатки со старых названий на новые
(«Труба Ø6» → «Труба медная 6.35мм», «Кронштейны» → «Кронштейн», «Болты» →
«Болт/гайка/шайба», «Металлопласт» → «Труба металлопластиковая ф16», и
аналогично для Ø9/Ø12/Ø15). Если на новом имени уже что-то было — количества
сложатся, старая строка удалится. Разовая операция, безопасно выполняется
при каждом запуске (после первого раза просто ничего не делает). В логах
при этом будет видно `Перенёс остаток материала: «...» -> «...»`.

## Функции

### Для клиентов (публичные команды)

- **Свободный текст с моделью кондиционера** — падение КПД обогрева по
  текущей погоде (как раньше — см. `classifier.py`).
- **`/calc`** — подбор рекомендуемой мощности: бот задаёт клиенту вопросы по
  очереди — площадь помещения (м²), высота потолков (до/выше 2.7 м), куда
  выходят окна (север/юг/восток/запад/нет окон — юг и запад считаются
  «солнечной» стороной), есть ли тепловыделяющая техника в помещении
  (компьютеры, холодильники, серверы, кухонное/торговое оборудование),
  последний ли этаж, физлицо или компания, контакт. Каждый фактор —
  независимая поправка +5% к расчётной мощности. Результат уходит клиенту
  сразу, а карточка заявки со всеми ответами — вам в личку (см.
  ADMIN_CHAT_IDS ниже). **Точную цену бот не называет** — в прайсе
  поставщика это дилерские/оптовые цены, а не ваша розница, показывать их
  клиенту нельзя.
- **`/warranty`** — проверка гарантии по установке, зарегистрированной на
  этот chat_id (регистрирует админ через `/new_install`, см. ниже).
- **`/city <город>`** — сменить город для погоды.
- **`/whoami`** — узнать свой chat_id (нужно для настройки админов).
- **`/help`** — список команд (сокращённый для клиентов, расширенный для
  админов).

### Для монтажников (INSTALLER_CHAT_IDS)

Отдельная, более узкая роль — только склад и акты, без доступа к лидам,
B2B-контрактам и регистрации установок:

- **`/actcalc`** — **посчитать акт по позициям**, как в бумажном шаблоне
  `АВР_Монтаж_Кондиционеров`:
  1. Выбираете группу мощности кнопкой: **7-9-12 / 18 / 24** (это группировка
     цен монтажа из акта, не путать с классами 09K/12K/18K/24K из КПД-калькулятора).
  2. Дальше три страницы позиций — **Работы**, **Материалы (цена
     фиксирована)**, **Материалы (укажите цену сами)**. Жмёте на нужную
     позицию → бот спрашивает количество (для позиций с фиксированной ценой
     этого достаточно — цену бот уже знает) → для позиций без цены в
     шаблоне (трубы конкретного диаметра, изолента, дюбели, выезд и т.п.)
     ещё спросит цену за единицу.
  3. «✅ Завершить акт» — бот считает итог, **автоматически списывает
     материалы со склада** (по тем же названиям, что в `/stock`/`/material`;
     если позиции ещё нет на складе — заводит её сам) и сохраняет акт в базу.
  Работы на склад не влияют — списываются только материалы.
- **`/material`** — быстрое кнопочное списание одного материала вне акта
  (для мелких случаев типа «докупили и сразу использовали 2 кронштейна»).
- **`/act Адрес`** — то же самое, что у админа (см. ниже): адрес + фото/
  «пропустить». Это отдельный, более простой механизм для случаев, когда
  бумажный акт с подписью клиента фотографируется как есть (без разбивки по
  позициям) — на будущее туда добавится распознавание фото через ИИ, чтобы
  автоматически вытаскивать ФИО/телефон/модель/адрес в базу клиентов.

Админы (ADMIN_CHAT_IDS) автоматически имеют и все права монтажника — им не
нужно отдельно прописываться в INSTALLER_CHAT_IDS.

### Для вас/Евгения (админ-команды, только для ADMIN_CHAT_IDS)

- **`/new_install`** — зарегистрировать установку для гарантии/напоминаний:
  ```
  /new_install Иванов +373... | TCL 12K простой инвертор | 12K | Тирасполь | 2026-09-01 | 24 | 555666777
  ```
  Поля через `|`: клиент/телефон, модель (обязательны только эти два),
  класс мощности, город, дата установки (по умолчанию сегодня), гарантия в
  месяцах (по умолчанию 24), chat_id клиента в Telegram. **chat_id клиента
  нужен, чтобы бот мог САМ написать клиенту** напоминание о ТО и запрос
  отзыва — без него установка просто лежит для внутреннего учёта. Узнать
  chat_id клиента можно, попросив его прислать боту `/whoami`.

- **`/stock`** — остатки склада.
- **`/stock_init Название | Ед.изм | Количество`** — завести материал (или
  переустановить остаток).
- **`/stock_use Название | Количество`** — списать расход текстовой командой
  (для админа; монтажникам удобнее кнопочный `/material` или полноценный
  разбор акта через `/actcalc`, см. выше).
- **`/stock_in Название | Количество`** — оприходовать материал (поступление
  на склад). Если материала ещё нет — заводит его сам с единицей «ед.» —
  поправьте потом через `/stock_init` при необходимости.

- **`/act Адрес`** — начать акт выполненных работ: бот попросит фото
  объекта (или напишите «пропустить»). Сохраняется в очередь. **Доступно
  и монтажникам** (INSTALLER_CHAT_IDS), не только админам.
- **`/acts_pending`** — список актов, ожидающих оформления (только админ).

- **`/b2b_add Договор | Точка | [Периодичность,дн]`** — добавить точку
  обслуживания по B2B-контракту (по умолчанию каждые 90 дней).
- **`/b2b_done Договор | Точка`** — отметить точку обслуженной сегодня.
- **`/b2b_list`** — статус всех точек (просрочено/в порядке).

### Автоматика (фоновая ежедневная задача)

Раз в день (`B2B_CHECK_HOUR_UTC`, по умолчанию 7:00 UTC) бот сам:

- пишет клиенту запрос отзыва через `REVIEW_REQUEST_DAYS_AFTER_INSTALL`
  дней после установки (по умолчанию 3) — ответ клиента сохраняется в
  таблицу `reviews`;
- пишет клиенту напоминание о сезонном ТО каждые
  `MAINTENANCE_REMINDER_INTERVAL_DAYS` дней (по умолчанию 180 ≈ раз в
  полгода) с момента установки/последнего напоминания;
- присылает вам (ADMIN_CHAT_IDS) сводку по просроченным B2B-точкам.

Это всё работает только для установок с указанным chat_id клиента.

## Настройка

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="токен от @BotFather"
export ADMIN_CHAT_IDS="123456789"            # ваш chat_id (и Евгения, если нужно, через запятую)
export INSTALLER_CHAT_IDS="555666777"        # chat_id монтажников (склад + акты, без остального)
python bot.py
```

Как узнать chat_id: попросите человека запустить бота и написать ему
`/whoami`, скопируйте число. Владельцам бота (полный доступ) — в
`ADMIN_CHAT_IDS`, монтажникам (только склад + акты) — в `INSTALLER_CHAT_IDS`.

Необязательные переменные:
- `AC_BOT_LOG_PATH` — путь к JSONL-логу диалогов КПД-калькулятора (по
  умолчанию `dialogs.jsonl`).
- `DB_PATH` — путь к файлу базы данных SQLite (по умолчанию `bot_data.db`).
- `REVIEW_REQUEST_DAYS_AFTER_INSTALL`, `MAINTENANCE_REMINDER_INTERVAL_DAYS`,
  `B2B_CHECK_HOUR_UTC` — тонкая настройка автоматики (см. выше).

## ⚠️ Персистентное хранилище на Railway

Файловая система на Railway **эфемерная** — при каждом новом деплое (после
`git push`) файл базы `bot_data.db` (и лог `dialogs.jsonl`) обнуляются.
Это означает потерю склада, лидов, установок, B2B-точек при каждом
обновлении кода!

Чтобы данные сохранялись между деплоями, подключите **Railway Volume**:

1. В сервисе на Railway откройте вкладку **Settings → Volumes**.
2. Нажмите **New Volume**, укажите mount path, например `/data`.
3. В Variables добавьте `DB_PATH=/data/bot_data.db` (и, если нужно,
   `AC_BOT_LOG_PATH=/data/dialogs.jsonl`).
4. Передеплойте — теперь база будет жить на постоянном диске, а не в
   контейнере, и переживёт любой следующий деплой.

Без volume бот прекрасно работает для тестирования, но реальные
данные клиентов копить в таком режиме нельзя.

## Как это устроено без ИИ

Как и раньше (см. предыдущую версию README) — классификация типа
кондиционера и расчёт КПД обогрева в `classifier.py` полностью
детерминированы: ключевые слова + оцифрованные таблицы + линейная
интерполяция, кнопки там, где нужно уточнение. Новые функции (`/calc`,
склад, акты, B2B) — обычная бизнес-логика без каких-либо ИИ-вызовов,
только SQLite (`db.py`) и Telegram API.

## Точность калькулятора мощности (`/calc`)

Формула — общепринятая отправная точка (100 Вт/м² при стандартном потолке),
с поправками +5% на последний этаж, +5% на солнечную сторону, +5% на
высокие потолки и +5% на тепловыделяющую технику. Это
ориентировочный расчёт для быстрой подсказки клиенту и квалификации лида,
**не инженерный точный подбор** — финальное решение всегда через менеджера
(бот сам это и говорит клиенту).

## Что можно доработать дальше

- **Распознавание фото актов (OCR) — следующий шаг, ещё не реализован.**
  Идея: монтажник фотографирует подписанный бумажный акт → бот через
  **Claude (Anthropic API)** распознаёт ФИО клиента, телефон, модель
  кондиционера, дату, адрес монтажа → автоматически заносит в базу
  клиентов/установок (`db.installations`). Провайдер зафиксирован как
  Claude (решено явно, не Gemini) — значит для этой функции понадобится
  `ANTHROPIC_API_KEY` и обычная оплата по использованию (только за эту
  функцию, остальной бот по-прежнему бесплатный). Пока что фото из `/act`
  просто хранятся с адресом, без автоматического разбора содержимого.
- Каталог позиций актов (`act_catalog.py`) — сознательное упрощение:
  показан объединённый список материалов для всех групп мощности, хотя в
  реальных бумажных шаблонах у каждой группы чуть разный набор диаметров
  труб/изоляции. Монтажник просто не трогает лишние позиции (оставляет 0).
  Если реальная практика покажет, что список слишком длинный/неудобный —
  можно сделать версию каталога отдельно под каждую группу.

- Все многошаговые диалоги (`PENDING_CITY`, `PENDING_CALC`, `PENDING_ACT`,
  `PENDING_REVIEW`, `CHAT_CITIES`) — в памяти процесса, теряются при
  перезапуске бота (в отличие от данных в SQLite). Для продакшена можно
  вынести и их в БД, но для диалогов длиной в пару сообщений это не
  критично — клиент просто начнёт заново.
- `/new_install` — однострочная команда с полями через `|`, без
  пошагового мастера с кнопками. Сознательный компромисс ради простоты
  реализации; можно заменить на пошаговый диалог, если формат окажется
  неудобным для ежедневного использования.
- Экспорт актов (`/acts_pending`) — сейчас просто список в чате; можно
  добавить выгрузку в Excel/PDF по образцу вашего шаблона актов.
- Уведомления о лидах и B2B идут всем ADMIN_CHAT_IDS сразу — можно
  разделить роли (например, лиды — только вам, B2B-просрочки — и вам, и
  Евгению).
- Ротация/архивация `dialogs.jsonl`, если поток сообщений станет большим.
